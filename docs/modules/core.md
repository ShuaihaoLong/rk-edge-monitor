# Core 中间层

## 职责

Core 提供不依赖具体设备的线程通信、服务生命周期和日志基础设施。代码位于 `include/core/`、`src/core/`，CMake target 为 `rkmon_core`，别名为 `rkmon::core`。

## 主要组件

- `BoundedQueue<T>`：有界生产者/消费者队列，支持阻塞 push、非阻塞 try_push、关闭、排空和 `drop_oldest`。
- `Mailbox<Event>`：控制事件队列，满时拒绝新命令，不丢弃旧控制命令；支持阻塞接收和唤醒回调。
- `IService` / `ServiceManager`：两阶段停止、依赖顺序启动、失败回滚、逆序 join。
- logger：同步控制台和轮转文件日志，配置级别、文件大小和保留份数。

## 线程与所有权

队列自身不拥有线程。调用方必须先停止生产/消费线程并 join，再销毁队列。队列关闭后不能重新打开；服务重启需要建立新队列。`size()` 和丢帧计数只是观测值，不能用“先 size 再 push”判断容量。

`ServiceManager` 仅由主控制线程调用。启动失败或异常会回滚已启动服务；停止先请求全部服务停止，再逆序等待。管理器不自动杀死卡住线程，具体服务必须提供可唤醒的 stop 路径。

## 故障和日志

工作线程不能静默结束，应通过故障回调上报。日志在所有工作线程退出后才能 shutdown；模块优先使用注入的 logger。日志初始化失败不应留下半初始化的 logger。

## 验证

CTest 覆盖队列溢出/关闭/丢旧、Mailbox 满和唤醒、ServiceManager 回滚和重复启停、日志初始化/轮转/并发写入。Core 不负责设备重连、业务重试或端到端指标。
